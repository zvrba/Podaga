      Interning

      This library provides a weak hash for interning objects and a simple mechanism for memoizing function results.

      Memoization

      Memoization is caching of previously computed function results to speed up further computations. In extreme cases, it can exponentially reduce running times; for example recursive computation of Fibonacci numbers. Memoization is supported through two types: MemoizeTInput, TOutput and MemoizedTInput, TOutput.

      The types seemingly support only functions with one argument and result, but this can be worked around by using ValueTuple. Internally, Memoize uses a DictionaryTKey, TValue to store previously computed results. The same Memoize instance can be used for multiple function exeuctions and retains the results of all previous executions.

      The snippet below exemplifies memoized recursive computation of Fibonacci numbers. The memoization argument is called recurse because it allows the function to invoke itself recursively, but skipping computations if the result is already cached.

      Memoized Fibonacci
      [Fact]
public static void FibonacciTest()
{
    Memoize<int, int> memo = new(Fib);

    var n5 = memo.Run(5);
    Assert.Equal(8, n5);

    var n6 = memo.Run(6);
    Assert.Equal(13, n6);
}

private static int Fib(int n, Memoize<int, int> recurse)
{
    if (n < 2)
        return 1;

    var n1 = recurse.Run(n - 1);
    var n2 = recurse.Run(n - 2);
    return n1 + n2;
}

      Interning

      Interning is applicable to types on which instance equality can be defined. Given an object instance I, the internator checks whether an equal instance I' is already interned, and if so, it returns I'. Otherwise, it remembers I and returns it. Obviously, an object instance must become immutable after interning.

      This library defines contract for internable values through three interfaces: IInternator, IInternable and IInternableTSelf. Because of subtleties around implementing an internable type, AbstractInternableTSelf is provided as a base class.

      Interning can be naively implemented with HashSetT, but the downside is that the hash-table is holding strong references to the stored objects, thus preventing otherwise unused objects from being garbage-collected. The library thus provides a WeakHash implementation of IInternator.

        Important

      It is important to dispose WeakHash instance when no longer needed. Leakage of allocated WeakGCHandleT instances is nevertheless prevented by the finalizer.

      WeakHash has the following characteristics:

      • Implements open addressing with linear probing. To improve collision-resistance, the internable object's GetHashCode method should "finalize" the hash by Mix. Resize is triggered when when the load factor has exceeded 75%, and all allocated GC handles count towards the load factor.

      • Stores instances of WeakGCHandleT for the stored objects, without resurrection tracking. (WeakReferenceT is a wrapper around a GCHanlde, but it incurs additional allocations because it's a reference type.)

      • Resizing triggers GC up to the 1st generation (using "Optimized" mode), and then counts surviving objects. It is thus possible that the table shrinks to a smaller capacity. Additional memory used is the new capacity.

      Lastly, the library provides an InternableListT. This type implements IListT as follows:

      • Small-storage optimization: up to MaxSmallCount elements are stored "inline" with the class, thus reducing allocations. When the number of elements exceeds the small count limit, the implementation acts as a wrapper over a ListT.

      • Deep equality of elements. If the element type implements IInternableTSelf, the elements are individually interned as well.
