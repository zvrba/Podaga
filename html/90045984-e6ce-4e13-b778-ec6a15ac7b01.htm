      Joinable tree framework

      This topic contains the following sections:

      • Introduction to persistent data structures
      • Introduction to augmented search trees
      • Framework features
      • Quick start

      This library provides a framework for working with augmentable binary trees. Being a framework, users are free to write their own algorithms that interoperate with the existing algorithms and data structures. By supporting arbitrary "value augmentations", the framework can be used to implement more "advanced" structures, such as interval trees without changing any of the core algorithms. Indeed, most of the algorithms are implemented as extension methods.

      Despite being more featureful (persistent, augmentable) than the standard SortedSetT, performance is only slightly worse.

      The implementation of this library is based on the following paper

      Guy Blelloch, Daniel Ferizovic, and Yihan Sun. 2022. Joinable Parallel Balanced Binary Trees. ACM Trans. Parallel Comput. 9, 2, Article 7 (April 2022), 41 pages.

      The current version does not exploit the possibility of parallelization.

      Introduction to persistent data structures

      A persistent data structure preserves its previous versions upon every modification; an example is ImmutableSortedSetT. As such, they are easier to use in multi-threaded scenarios where modifications by one thread must not affect other threads' view of the data. The downside of persistence is increased memory pressure and negative performance impact. Wikipedia article provides extensive background with further references.

      Because most developers are used to the convenience of ordinary mutable data structures (e.g., List<T>), this library introduces the concept of cloning. The joinable collections behave as ordinary mutable collections, but cloning creates independent "copies" of the original collection such that modifications to one are invisible to the other.

        Note

      Cloning is cheap: only a fresh collection object is created whereas the actual data is copied lazily upon mdification of either the original or the cloned collection. In operating systems, this is also known as copy-on-write semantics which enables space-efficient sharing of memory pages.

      The collections consint internally of nodes which always carry a transient tag which is a unique instance of TreeJoinT. The transient tag is also attached to the collection itself so that it knows which nodes must be physically copied before their contents is modified.

      The library is delivered with a test suite that tests correctness using all combinations of predefined add/remove patterns (PermutationGenerators).

      Introduction to augmented search trees

      This framework allows the value type to be partitioned into two parts: an immutable key part and a mutable augmentation part. For correct operation, the augmentation part must form a monoid and the key part must not be modified after when the node is a member of a tree.

      The framework provides a size augmentation out of the box, which enables efficient (logarithmic) indexed access to elements in sorted order.

      A longer introduction to augmented data structures may be found in CLRS "Introduction to algorithms". Short lecture notes are also available, for example, here.

      Framework features

      The tree framework provides the following fetures out of the box:

      • AVL and weight-balanced trees.

      • Automatic adaptation of IComparerT to ITaggedValueComparerT for easier interoperability with existing collections.

      • On-demand persistence through cloning.

      • User-provided monoidal augmentations (useful for implementing, e.g., interval trees). Indexing augmentation, i.e., logarithmic element access by index in sorted order is built-in.

      • Adapters to standard interfaces: ICollectionT, IReadOnlyListT (indexing in sort order), ISetT, IDictionaryTKey, TValue.

      • The adapters are "views" over the same tree and are cheap to construct. In particular, they allow to convert a "dictionary view" of the tree to a "set view", thus allowing for efficient set-operations over dictionaries.

      • TreeIteratorT allows position-based, non-recursive iteration over tree elements in sorted order.

      • Transparent: most algorithms are implemented as extension methods over TreeJoinT and TreeIteratorT.

      Quick start

      Main types are AvlJoinT and WBJoinT. An example of creating a standard collection of integers:

      C#
      var coll = AvlJoin<int>.NewCollection(Comparer<int>.Default);

      Other collection factory methods are available through static extension methods in JoinableAvlTreeCollectionFactory and JoinableWBTreeCollectionFactory classes. Collection conversions and non-destructive set operations are available through instance extension methods in AdaptedJoinableTreeExtensions class.

      See the source code in benchmark and test projects for further usage examples.
